# PT-Plugin-Plus 产品介绍

## 一句话说明

PT-Plugin-Plus（PTPP）是一款帮助 PT 用户统一管理站点搜索、用户数据、下载器、收藏、辅种和备份的 Chrome 扩展。

## 为什么做这个项目

原版 PT-Plugin-Plus 使用 Manifest V2。随着 Chrome 停止支持 Manifest V2，原版项目无法继续作为现代浏览器扩展使用。PTPP 在保留原版常用功能和交互习惯的基础上，迁移到 Manifest V3，并继续兼容旧版数据。

## 主要使用场景

### 找资源

在一个搜索页面中同时查询多个已配置站点，使用过滤、排序、影片资料和搜索快照整理结果。

### 管理下载

PTPP 支持多个下载器。用户可以设置一个全局默认下载器，也可以给某个站点绑定独立的下载器、保存目录和标签。站点绑定优先于全局默认设置，适合把不同站点的内容分开保存。

### 了解账号状态

“我的数据”可以集中查看站点等级、分享率、上传/下载量、做种、积分、历史和图表，并支持批量打开站点或刷新用户数据。

### 管理长期任务

收藏与分组、辅种任务、下载历史和常驻站点工具栏组成了 PTPP 的日常工作流：看到资源后可以快速复制、收藏、推送或创建辅种任务。

### 保护和迁移数据

用户可以使用本地 ZIP 或 WebDAV 保存配置和业务数据，也可以使用 AES 加密备份。旧版 PTPP 的站点、下载器、目录、Cookies、历史、收藏、辅种和备份设置可以迁移到新版。

## 与 PT-depiler 的关系

PTPP 与 PT-depiler 都使用 Manifest V3，并共享部分站点定义、下载器适配器和底层数据结构。PTPP 仍以归档版 PTPP 的界面和功能范围为产品基准，只选择性吸收 PT-depiler 的底层改进。

两者最重要的产品差异是下载目标：PT-depiler 不计划实现 [issue #454](https://github.com/pt-plugins/PT-depiler/issues/454) 中讨论的“站点绑定下载器与下载目录”设计，而 PTPP 将其作为核心能力继续维护。这也是 PTPP 需要独立升级和维护的主要原因。

PTPP 不会因为复用底层代码而引入 PT-depiler 独有的媒体服务器、原生通信桥或其他产品入口。

## AI 助手

AI 助手是可选功能。PTPP 只提供界面和经过限制的业务接口，模型请求由独立的本机 MCP 服务处理。MCP 未连接时，AI 入口会自动隐藏；连接后，用户可以在当前页面询问站点数据、搜索结果或下载器状态。

AI 不能直接读取原始浏览器存储、Cookies、密码或完整页面 DOM，也不能直接删除备份或执行下载推送。

## 项目边界

- 面向 Chrome Manifest V3；其他浏览器不在当前首发范围内。
- 站点能力取决于站点定义和用户的登录状态。
- 不绕过验证码、Cloudflare 或站点的安全验证。
- 不提供遥测、广告或项目方数据中转服务。
