# 主次列响应式表格与设置导航设计

## 背景

`4512a718` 用全局界面缩放和共享 sticky 操作列处理宽表格，但实机证明 hover 时操作列会变成透明背景，使其下方滚动列穿透到按钮上。老板版 PTPP 通过响应式列宽处理宽表格，最新 PTD `15f9c4db` 使用普通横向滚动；两者都不依赖应用级缩放。

左侧“常规设置”菜单指向父路由 `SetBase`。首次访问 `/set-base` 会匹配默认子路由 `SetBaseGeneral`，再次按父路由名称导航则只留下父组件，子 `router-view` 为空，Tab 模型也变成不存在的 `SetBase`。

## 决策

1. 撤回 PTPP 全局界面缩放、Chrome/DPI 诊断入口和 teleport overlay 缩放适配；100% 浏览器缩放重新成为唯一布局基线。
2. 仅搜索结果页保留共享宽表格和顶部同步横向滚动条；其他页面继续使用原生 `v-data-table` 和原有展示方式。
3. 搜索结果表头显式分为 `primary`、`secondary`、`action`：
   - `primary` 是识别当前记录所需的站点、名称或标题，位于表格前部但不 sticky。
   - `secondary` 保留完整最小宽度，允许横向滚动并从 action 列下方经过。
   - `action` 固定在右端，保持页面原有按钮，且在普通、斑马纹、hover、选中和选中-hover 状态下都使用完全不透明的背景。
4. action 单元格使用高于普通列的稳定层级和左侧分隔阴影；滚动内容可以位于其下方，但任何像素、文本、图标、tooltip activator 都不得穿透固定区。
5. 表格响应式逻辑不得改写用户保存的列、排序、分页或选择状态。
6. 左侧菜单为存在默认子路由的页面直接导航到默认子路由；`SetBase` 页面再提供父路由兜底和合法 Tab 值归一化。

## 页面角色约定

| 页面     | Primary         | Action   | Secondary                             |
| -------- | --------------- | -------- | ------------------------------------- |
| 搜索结果 | `site`, `title` | `action` | 分类、大小、上传/下载/完成/评论、时间 |

下载历史、收藏、辅种、我的数据、我的下载器、搜索快照、下载服务器、站点、下载目录、搜索方案、备份及历史和日志不参与该角色映射，保持各自原生表格布局。

## Git 策略

`4512a718` 已推送，禁止 `reset --hard` 或 force-push。执行时使用 `git revert --no-commit 4512a718...` 产生反向变更，再在同一工作区重新加入经过修正的共享表格和设置导航，最终形成一个带 extended description 的替代提交。这样保留远端历史，又不会发布一个短暂缺少宽表格能力的中间提交。

## 验收条件

- 1280×720、1536×864、1920×1080 和 Chrome 80%/100%/125% 下均无文档级横向溢出。
- action 列横向位置在滚动期间不变；secondary 列确实从其下方滚动，但五种行状态的 action 背景 alpha 始终为 1。
- 搜索结果按钮可点击，hover/焦点/tooltip 出现时不显示下层分类、大小或活跃度文本。
- 搜索结果页的顶部滚动条、分页、列设置和选择状态正常；其他现有表格页面不渲染共享响应式外壳并保持原有布局。
- 连续点击左侧“常规设置”至少三次，路由始终为 `SetBaseGeneral`，默认“界面与交互”Tab 保持选中且内容不为空。
- 类型检查、完整测试、生产构建、MV3/商店审计、运行时冒烟和 Chrome Extension CDP 回归全部通过。
